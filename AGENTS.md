# Работа над buisnes board

Прочитай `CLAUDE.md` и `.claude/skills/git-workflow/SKILL.md`: стек, проверки, миграции и порядок слияния общие для всех агентов. Пиши по-русски. Не меняй чужие незакоммиченные файлы.

## ИИ внутри продукта

Этот файл направляет агентов разработки. ИИ в приложении получает инструкции из `backend/src/ai_instructions.md`, а инструменты — из общего `src/aiToolCatalog.json`. Изменение только AGENTS.md не меняет поведение ИИ продукта.

- При изменении инструмента проверь серверный контракт, клиентскую валидацию, выполнение и результат, возвращаемый модели. Не считай обещание модели доказательством выполнения.
- Созданный/изменённый HTML проверяется через `read_html_test` в том же sandbox, что и карточка. Нужны конкретные входы, действие и ожидаемый результат. После правки кода старая проверка недействительна. Ошибки запуска должны возвращаться ИИ, а непроверенный результат — оставаться явно непроверенным.
- Не открывай виджетам доступ к странице приложения, хранилищу или сети ради исправления теста. Локальные submit-события не должны отправлять данные или менять страницу.
- BPMN редактируется существующим адаптером. Сохраняй ID и проверяй реальные связи с пунктами; учитывай явно заданных исполнителей.
- Заголовки документов и моделей бери из актуального проекта, без примерных названий в интерфейсе. При вписывании учитывай чат и боковые панели.

## Проверки

Функциональные проверки должны охватывать только изменённые функции и непосредственно затронутые ими сценарии. Не запускай проверки других подсистем просто потому, что они есть в проекте.

- [ ] Определи, какие функции изменены и какие связанные сценарии могут быть затронуты.
- [ ] Для изменений кода выполни обязательные общие проверки: `npm run check`, `npm run build`, `cargo test --manifest-path backend/Cargo.toml`. Это отдельные проверки типов, сборки и базовых тестов, а не повод вручную проверять все функции приложения.
- [ ] Запусти только относящиеся к изменению функциональные тесты. `npm run test:html` и `/tests/html-runtime.html` нужны при изменении HTML-объектов, их sandbox или выполнения; `npm run test:ai` и `/tests/ai-tools.html` — при изменении ИИ, его инструментов или непосредственно затронутых контрактов. Правка дерева, меню или значков сама по себе не требует проверок HTML и ИИ.
- [ ] Проверь изменённый интерфейс и его действия во вкладке localhost внутри Codex. Отдельные окна браузера не открывай.
- [ ] После успешных проверок не расширяй и не повторяй их без новых правок, ошибок или конкретной обнаруженной зависимости.

Для изменений только документации или инструкций достаточно проверки diff; функциональные тесты не нужны.

Различай тест с подставным генератором, проверку настоящей модели и проверку развёрнутого сервера. Не заявляй, что непроверенные сценарии прошли.
