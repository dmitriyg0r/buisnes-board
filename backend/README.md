# Бэкенд «buisnes board»

Rust (axum + sqlx) и PostgreSQL.

## Запуск

```bash
docker compose up -d db          # PostgreSQL 16 на порту 5432
cp backend/.env.example backend/.env
npm install && npm run build     # сборка фронтенда в dist/
cd backend && cargo run --release   # миграции применяются при старте
```

Сервер слушает `127.0.0.1:8080` и сам отдаёт собранный фронтенд из `FRONTEND_DIR` (в `.env.example` — `../dist`):
открывайте http://127.0.0.1:8080. Для разработки можно вместо этого запустить `npm run dev`:
Vite проксирует `/api` на бэкенд.

## Секреты пользователей

Ключ Codex хранится в таблице `integrations` только в зашифрованном виде (AES-256-GCM, id пользователя входит в
проверяемые данные). Ключ шифрования берётся из `SECRETS_KEY` (`openssl rand -hex 32`); без него подключение
сервисов отключено, остальное работает. Потеря или смена `SECRETS_KEY` делает сохранённые ключи нечитаемыми:
их придётся подключить заново. Ключ в ответах API не возвращается, показываются только последние четыре символа.

## Боевой режим

- Выставьте `COOKIE_SECURE=true` и поставьте перед сервером HTTPS (nginx, Caddy): cookie сессии получит флаг `Secure`.
- `ALLOW_REGISTRATION=false` отключает самостоятельную регистрацию, когда нужные аккаунты уже созданы.
- `DATABASE_URL` указывает на ваш PostgreSQL; для удалённой базы с обязательным TLS нужно включить TLS-фичу sqlx.
- Ответы сервера содержат `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`.
- Резервные копии: `pg_dump` базы; файлов проекта сервер не хранит.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | состояние сервера и БД |
| POST | `/api/auth/register` | регистрация `{ email, password, name, role? }`, сразу открывает сессию |
| POST | `/api/auth/login`, `/api/auth/logout` | вход и выход |
| GET, PATCH | `/api/auth/me` | текущий пользователь, смена имени и роли |
| GET, POST | `/api/projects` | список проектов пользователя, создание пустого проекта |
| GET, PATCH, DELETE | `/api/projects/:id` | проект |
| GET, PUT | `/api/projects/:id/model` | модель; PUT принимает `{ version, data }`, при устаревшей версии ответ 409 |
| GET, POST, DELETE | `/api/projects/:id/issues` | замечания проекта: список, создание (`ref` — ключ клиента), удаление всех |
| PUT | `/api/projects/:id/issues/by-ref/:key` | создать или обновить замечание по ключу; так хранится статус автозамечания |
| PATCH, DELETE | `/api/issues/:id` | замечание; статусы: open, asked, answered, fixed, closed |
| GET, PUT | `/api/settings` | настройки профиля |
| GET, PUT, DELETE | `/api/integrations/codex` | подключение Codex: состояние, сохранение ключа OpenAI (перед записью ключ проверяется запросом к OpenAI), удаление |
| POST | `/api/integrations/codex/check` | повторная проверка сохранённого ключа |

Модель хранится одним документом jsonb (`processes` с BPMN 2.0 XML, `docs` с Markdown, `links`, `cardLinks`, `sources`, `meta`) с номером версии. Новый проект пуст: модели, документы и источники появляются, когда пользователь добавляет материалы; их может быть несколько.
Входа пользователей пока нет: настройки лежат под одним ключом.

## Вход

Все маршруты, кроме `/api/health` и `/api/auth/*`, требуют входа. Сессия лежит в cookie `bb_session`
(HttpOnly, SameSite=Lax) на 30 дней; в базе хранится только SHA-256 токена. Пароли хешируются argon2id.
Проекты, замечания и настройки принадлежат пользователю: чужой проект отвечает 404.
После 10 неудачных входов с одной почтой вход блокируется на 10 минут (счётчик в памяти сервера).

Первый зарегистрированный пользователь забирает проекты и настройки, созданные до появления входа.
`ALLOW_REGISTRATION=false` отключает самостоятельную регистрацию, `COOKIE_SECURE=true` нужен за HTTPS.

## BPMN

- **Просмотр** диаграммы на карточке модели — [bpmn-visualization](https://github.com/process-analytics/bpmn-visualization) (Apache-2.0), без водяного знака.
- **Редактор** — собственный движок диаграмм с первым набором элементов BPMN. Это ранняя версия: доступны основные события без дополнительных определений, типы задач и шлюзов, свёрнутый подпроцесс, горизонтальные дорожки, объекты данных, аннотации, потоки управления и ассоциации. Сложные модели, включая вложенные или вертикальные дорожки, пока могут открываться только частично и без сохранения. Экспорт сохраняет исходный XML.
- Диаграмма хранится как BPMN 2.0 XML, шаги для связей с регламентом и покрытия берутся из него по идентификаторам
  элементов. Редактор открывается карандашом на карточке модели, в нём есть импорт и экспорт `.bpmn`.

## Документы

Документ хранится как Markdown. Редактор — [MDXEditor](https://mdxeditor.dev) (MIT): один экран, разметка применяется сразу
(«# » — заголовок, «- » — список, «**текст**» — жирный), исходный Markdown открывается переключателем. Заголовки до третьего
уровня становятся пунктами документа, к ним привязываются шаги моделей; идентификаторы пунктов сохраняются при правке.
