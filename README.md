# buisnes board

Доска бизнес-процессов: BPMN-схемы, документы в Markdown, замечания. Фронтенд — React + Vite + TypeScript, бэкенд — Rust (axum + sqlx) + PostgreSQL.

## Быстрый старт (2 команды)

Нужны: [Node.js 20+](https://nodejs.org), [Docker Desktop](https://www.docker.com/products/docker-desktop), [Rust](https://rustup.rs).

```bash
npm run setup     # один раз: зависимости, backend/.env, база в Docker
npm run dev:all   # каждый день: база + бэкенд + фронтенд
```

Откройте http://localhost:5173 и зарегистрируйте себя (первый запуск Rust-бэкенда собирается пару минут).

## Интерактивные HTML-объекты

В окне «Добавить объект» выберите «HTML-объекты» → «Интерактивный HTML». Редактор показывает код с подсветкой HTML/CSS/JavaScript и работающий предпросмотр рядом; название и код сохраняются автоматически. Можно импортировать и экспортировать `.html`. Разделитель меняет ширину панелей, двойной щелчок возвращает равные ширины. Каждую панель можно свернуть и развернуть; расположение запоминается. Разделитель также управляется стрелками с клавиатуры.

На доске объект работает прямо внутри карточки. Перемещайте её за заголовок, меняйте размер за нижний правый угол, создавайте связи через точки по краям. Карандаш открывает код. Удаление и восстановление через историю работают как у остальных карточек.

HTML выполняется в изолированном iframe: доступны встроенные CSS и JavaScript, изображения `data:` и `blob:`. Доступ к странице приложения, cookies и хранилищу закрыт; внешние скрипты, сетевые запросы и отправка форм заблокированы. Значения в работающем виджете живут до его перезапуска; в проекте сохраняется исходный код.

## ИИ на канвасе

Чат умеет читать, создавать, менять и удалять объекты всех типов; редактировать существующие BPMN-схемы через операции редактора; писать интерактивный HTML и Markdown; управлять связями, свойствами, замечаниями, расположением и размером карточек. Можно попросить открыть редактор, показать свойства, экспортировать объект, изменить масштаб, сетку и боковые панели, отменить или вернуть изменение доски.

Например: «Создай HTML-калькулятор стоимости и свяжи его с регламентом», «Добавь задачу согласования в этот процесс», «Закрой замечание и запиши решение», «Разложи объекты без наложений и впиши доску в экран». Управление аккаунтом, интеграциями и проектами вне канваса в эти команды не входит. Источники PDF/DOCX представлены карточками: содержимое файлов ИИ не читает.

Клиент и сервер проверяют единый каталог `src/aiToolCatalog.json`. Перед записью пакет проверяется на копии модели; ошибки возвращаются ИИ для исправления. Созданный или изменённый HTML обязательно проходит `read_html_test`: отдельная копия в том же sandbox получает тестовые значения, нажатия кнопок и проверки результата. Ошибки JavaScript и несовпадения возвращаются ИИ; до успешного теста готовность виджета не подтверждается. Тест проверяет заданные примеры, а не все возможные входы. Состояние виджета на доске при этом не меняется.

В чате можно развернуть журнал фактически выполненных действий. Изменения модели входят в обычную историю отмены; замечания сохраняются отдельно с историей статусов. Если объект изменился во время генерации, ИИ должен перечитать его перед заменой содержимого. Один запрос ограничен шестью шагами чтения и выполнения. Рабочие инструкции ИИ находятся в `backend/src/ai_instructions.md`; `AGENTS.md` задаёт правила для агентов разработки.

«Вписать» сворачивает открытый чат, сохраняя переписку, и размещает карточки в свободной области экрана. На узком канвасе строка чата находится выше миникарты и управления масштабом, чтобы они не перекрывали кнопки ввода.

Проверка команд: `npm run test:ai`; сценарии BPMN с DOM — открыть `/tests/ai-tools.html` на локальном Vite. `/tests/html-runtime.html` проверяет формы, ошибки и изоляцию HTML; `/tests/canvas-quality.html` — стенд раскладки и подписей документов. Тесты агента используют подставной генератор, без обращения к внешней модели.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev:all` | поднимает всё сразу |
| `npm run check` | проверка типов + `cargo check` — запускайте перед коммитом |
| `npm run build` | сборка фронтенда |
| `npm run test:html` | совместимость, сохранение и слияние HTML-объектов, политика предпросмотра |
| `npm run test:ai` | контракт, выполнение команд канваса и многошаговые сценарии ИИ |
| `docker compose down -v` | сбросить локальную базу с нуля |

## Как работать командой

1. `git pull` → новая ветка: `git switch -c feature/что-делаем`.
2. Пишете код (в том числе с Claude Code: в корне лежит `CLAUDE.md` с правилами проекта, он подхватывается сам).
3. `npm run check` → коммит → `git push` → Pull Request в `main`. CI проверит сборку.
4. Один человек смотрит PR и мержит. В `main` напрямую не пушим.

Правила, которые легко нарушить:
- **Миграции БД** (`backend/migrations/`) только добавляем новыми файлами `0006_...sql`, старые не правим — иначе у всех сломается база.
- **Секреты** (`backend/.env`) не коммитим, он в `.gitignore`. Новые переменные добавляйте в `backend/.env.example`.
- Мелкие PR лучше больших: легче ревьюить и меньше конфликтов.

Подробности про бэкенд, секреты и боевой режим — в [backend/README.md](backend/README.md).
