# Слияние с main

Агентам разрешено пушить в `main`, но только если **все конфликты устранены** и проверки зелёные. Человеку не нужно сливать ветку с `main` вручную: это делает агент.

## Порядок

1. Работай в отдельной ветке (`feat/…`, `fix/…`), коммить только свои файлы.
2. Перед слиянием подтяни свежий `main`: `git fetch origin && git merge origin/main` в своей ветке. Не используй `git stash`, `git reset --hard` и `--force` на общих ветках.
3. Устрани **все** конфликты. Не оставляй маркеры `<<<<<<<`, `=======`, `>>>>>>>` (проверь `git grep -n '^<<<<<<<\|^>>>>>>>'`). Если обе стороны правили один файл, оставь изменения обеих. Если смысл конфликта неясен (одна и та же логика изменена по-разному), не угадывай: спроси автора.
4. Запусти проверки: `npm run check`, `cd backend && cargo test`, `npm run build`. Всё должно пройти.
5. Пуш в `main` разрешён, когда шаги 2–4 выполнены и слияние обычное (без `--force`). Если нужен обзор или CI, открой Pull Request в `main`, дождись зелёных проверок `backend` и `frontend` и только потом вливай.
6. Если конфликт в ветке коллеги, сливай `main` в его ветку отдельным merge-коммитом и пушь без force, не переписывая его историю.

## Нельзя

- Пушить в `main` с неразрешёнными конфликтами или падающими проверками.
- `git push --force` в `main` и в чужие ветки.
- Редактировать или удалять существующие миграции в `backend/migrations/`, коммитить `backend/.env`, `.pgdata`, `node_modules`, `dist`, `target`.
