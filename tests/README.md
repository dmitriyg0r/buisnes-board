# Проверки движка диаграмм

Выбирай функциональные проверки только для изменённых функций и непосредственно затронутых сценариев. Этот список — каталог стендов, а не требование запускать их все. Для правок дерева или меню не нужны проверки HTML и ИИ, если изменение не затрагивает эти подсистемы. Общий чеклист находится в `AGENTS.md`.

Качество ИИ и HTML: `/tests/ai-tools.html` проверяет команды и обязательную самопроверку виджета, `/tests/html-runtime.html` запускает расчёты и ошибки в реальном sandbox. `/tests/canvas-quality.html` — ручной стенд вписывания с открытым/свёрнутым чатом и актуального названия документа в замечании. Эти стенды не записывают данные на сервер.

## BPMN-адаптер

Запустите `npm run dev`, затем откройте в браузере `/tests/bpmn.html` на адресе Vite. Страница запускает проверки в настоящем браузере: работа с DOM/XML, создание, изменение и удаление элементов и потоков, совместимость с существующим парсером, отказ от записи неподдерживаемых и повреждённых моделей. В конце отображается число ошибок.

Дополнительные проверки: `/tests/bpmn-events.html` — определения событий; `/tests/bpmn-data.html` — хранилища, ассоциации данных и сохранность импортированных элементов. `/tests/editor.html` — интерактивный стенд редактора с тестовой моделью, без записи в базу данных. `/tests/edge-edit.html` — браузерная регрессия редактирования маршрутов, клавиатуры и истории; события перетаскивания моделируются программно. `/tests/resize-corners.html` — изменение размера с четырёх углов и отмена с клавиатуры. `/tests/connection-ports.html` — наведение и число точек связи.

Эти проверки не заменяют браузерные сценарии интерфейса, проверку реальных файлов или проверку соответствия сохранённого XML схеме BPMN 2.0.2. Для проверки XSD используйте опубликованные OMG файлы `BPMN20.xsd`, `Semantic.xsd`, `BPMNDI.xsd`, `DC.xsd` и `DI.xsd` в одном каталоге и команду `xmllint --noout --schema BPMN20.xsd файл.bpmn`.

Маршрутизация связей: `/tests/routing-regression.html` — обход объектов и перемещение; `/tests/edge-constraints.html` — ограничения ручного маршрута; `/tests/connection-magnet.html` — привязки, предпросмотр и история с синтетическими событиями. Геометрию можно проверить командой `node --experimental-strip-types tests/orthogonal-routing.ts`.

Управление редактором: `/tests/inline-label.html` — ввод в текстовом блоке; `/tests/selection-editor.html` — групповое выделение, перемещение и панорамирование с синтетическими pointer-событиями.

Выравнивание: `/tests/modeling-grid.html` проверяет сетку, её настройки и размещение; `/tests/modeling-guides.html` — направляющие и равные интервалы. Чистые геометрические проверки: `node --experimental-strip-types tests/diagram-alignment.ts`.

EPC/UML для ИИ: `/tests/ai-tools.html` включает создание, чтение, правки, стабильность ID, ошибки и экспорт независимых моделей. `/tests/ai-models.html` показывает результат фиксированных команд ИИ во всех пяти нотациях и открывает настоящий редактор; данные остаются в памяти. Эти стенды не вызывают настоящую модель.

Уточнения и отмена: `/tests/chat-lifecycle.html` проверяет настоящий компонент чата и агент с управляемым подставным генератором: уточнение во время ответа, отбрасывание устаревшего плана, сохранение исходной задачи, немедленная отправка после отмены. Rust-тесты отдельно проверяют отмену молчащего потока и освобождение очереди. Это не проверка настоящей модели или развёрнутого сервера.

Канвас: `/tests/canvas-interactions.html` — перенос сквозь карточку и наложение, сохранение координат в модели, добавление без раздвигания, отмена/повтор и точное совпадение маршрута с движком EPC. Дополнительно проверяются сохранение линии при частичном и полном наложении, перекрытие порта третьей карточкой, создание связи между наложенными карточками и восстановление обычного маршрута после разнесения. Синтетические pointer-события проверяют обработчики React; нативное перетаскивание и создание связи мышью проверяются отдельно в интерфейсе. Стенд не пишет на сервер.

Дерево моделей: `/tests/tree-navigation.html` — одинаковые несжимаемые значки, отсутствие корзин и подписей нотаций, меню «⋯», поиск EPC/UML/BPMN вне экрана, выделение карточки и строки, повторный поиск, открытие редактора, закрытие меню через Escape, удаление моделей со связями и восстановление через отмену. Стенд проверяет реальные Tree/Canvas на локальных данных без записи на сервер.

Ширина навигатора: `/tests/tree-width.html` — однострочная обрезка названий всех видов объектов, подсказки, сохранение размера значков, изменение ширины мышью и клавиатурой, сохранение ширины и восстановление после сворачивания. Используется отдельный ключ настроек стенда.

Совместные модели: `/tests/model-source-merge.html` проверяет слияние по ID и свойствам для BPMN, EPC и четырёх UML-нотаций, удаление, историю и маршруты при перемещении разных концов связи. Разные свойства объединяются; для одного свойства действует последнее сохранение. Если объединённая диаграмма не проходит проверку адаптера, синхронизация останавливается с ошибкой и сохраняет локальную копию.

Для проверки настоящего HTTP/PostgreSQL/SSE используйте **отдельный временный backend** на `127.0.0.1:8080` с `COOKIE_SECURE=false`, `ALLOW_REGISTRATION=true` и изолированной БД. Затем запустите `python3 tests/model-collaboration-http.py`. Скрипт создаёт временные аккаунты/проект, проверяет права, валидацию присутствия, SSE и конфликт версий; формирует игнорируемый Git файл `tests/model-collaboration-config.json`. Основную или рабочую БД для этого стенда не используйте.

Для двух вошедших пользователей откройте `/tests/model-collaboration-live.html?user=A` через `127.0.0.1`, а `?user=B` через `localhost` (разные cookie в браузере). Стенд использует настоящие `useSync`, `usePresence`, редакторы и API. Проверьте одновременные правки разных элементов, появление правок во втором редакторе без закрытия, отмену своей правки после чужой, сохранение при немедленном закрытии, курсор при панорамировании/масштабировании, кружок с инициалами на карточке и его исчезновение после закрытия редактора. Для BPMN отдельно проверьте подтверждение удаления привязок и их восстановление при отмене удаления элемента. Рамка фокуса самого полотна не показывается, выделение объектов сохраняется.

После проверки остановите временный backend и БД, удалите `tests/model-collaboration-config.json`. Это проверка локального сервера, не подтверждение обновления развёрнутого сайта.
